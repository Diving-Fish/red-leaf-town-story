# 核心玩法与成长系统

本文记录红叶镇物语在扩充内容前需要保持稳定的游戏规则。具体数值仍由数据配置和模拟结果调整，但任务、伙伴、主角成长与品质判定的边界不应随单个活动或角色改变。

## 设计目标

- 主角成长决定生产体系的上限，伙伴负责形成不同的生产方案，抽卡不能替代长期游玩。
- 每块土地、畜栏、加工设备等生产格都可以独立安排任务，不强制同一产业同时生产相同内容。
- 伙伴在生产格中的站位可以产生相邻或定向支援，让空间布局成为构筑的一部分。
- 高星伙伴提供更丰富的机制和更高的培养上限，但低星伙伴仍应有明确用途。
- 时间、产量和品质是三条不同的收益轴，避免所有配置最终只比较一个总倍率。
- 稀有品质和特殊机制提供惊喜，不成为主线成长的硬性门槛。

## 产业

首批规划七种产业：

| 产业 | 典型任务 |
| --- | --- |
| 农作 | 播种、照料、收获作物 |
| 采集 | 林地、草场等区域采集 |
| 矿产 | 采矿、勘探矿脉 |
| 水产 | 垂钓、养殖、捕捞 |
| 畜牧 | 饲养动物、取得畜产品 |
| 加工 | 使用原料制作商品 |
| 探索 | 派遣、发现地点和特殊事件 |

产业是能力值、伙伴倾向、天赋树和内容解锁的共同分类。静态配置和存档只保存稳定 ID，显示名称不参与规则判断。

## 生产格、驻场与任务

土地、畜栏、采集点、矿点和加工设备都是不同类型的“生产格”。每个生产格独立保存一个进行中的任务，因此玩家可以在不同土地上同时种植不同作物。

伙伴先驻场到具体生产格，再由生产格开始任务：

1. 每个生产格默认有一个负责人位置，通过对应产业的中期天赋解锁第二个协作者位置，永久硬上限为两人。
2. 伙伴必须拥有对应的产业倾向，同一伙伴只能驻场在一个生产格。
3. 对应产业的“总编制”限制同时驻场的伙伴数量；两人负责同一格时占用两个编制名额。
4. 没有伙伴负责的生产格仍可正常工作，只使用主角的对应产业能力。
5. 开工后，本任务直接使用的伙伴以及提供支援效果的伙伴都会被锁定，不能撤下或移动。
6. 到达完成时间后，本任务产生的锁定引用自动解除，不要求玩家先领取产物。
7. 伙伴可以保留在原生产格作为下次任务的默认配置；没有进行中的引用时，玩家可以自由调动。
8. 首版不提供中途换人或取消任务，避免时间、体力、道具返还和空间效果重算产生歧义。

当前实现已经落地农田、采集、加工和矿产的单负责人闭环：每块土地、采集点、加工工位或矿点只有一个伙伴位置，各产业基础编制和伙伴有效等级上限由 `data/game.json` 的产业规则配置。农田、加工和矿产没有伙伴也能由玩家完成；采集必须先派驻一名具有采集倾向的伙伴，玩家不能独自开工。空间支援、第二协作者和特性效果暂不生效，但任务快照已经固定保存 `support_partner_ids` 与 `applied_effects` 空结构，后续扩展不需要改变任务边界。

生产格数量、产业总编制和单格协作者位置是三种独立成长资源：生产格提高并行任务数，总编制决定有多少伙伴可以同时驻场，协作者位置允许把两名伙伴集中在一个高价值任务上。因为效率收益递减，分散驻场更利于总体吞吐；因为品质存在门槛，集中驻场更适合冲击高品质和伙伴联动。

任务在开始时生成结算快照，至少记录：

- 内容 ID、生产格 ID、开始和完成时间；
- 直接负责本格的伙伴、提供空间支援的伙伴，以及它们的有效等级、突破状态和相关能力；
- 主角产业能力及会影响本任务的天赋；
- 生效的设施、天气、季节、肥料、伙伴特性及其来源；
- 最终使用的时间、产量、品质参数和规则版本。

任务进行期间发生的伙伴升级、突破、天赋加点或配置热更新只影响下一次任务。服务器依据开工快照和服务器时钟懒结算，客户端倒计时不参与结果判断。到达 `ready_at` 后生产格仍可保持“待领取”状态，但本任务已不再锁定伙伴；首次读取或操作时生成并保存产出结果，不能通过重复请求重掷品质。

农作任务快照当前还会保存作物产出物 ID、产量上下限、收获经验，以及 `Q`、四个品质阈值、分布宽度、奇迹资格与五档最终概率。收获必须使用这些快照值，不能重新读取可能已经更新的作物配置。伙伴可以在作物成熟后、领取前移动到另一块土地；旧任务仍按开工快照结算。任务成熟后的首次读取或收获会在同一次原子更新中抽取一次产量，再为每一件产物单独判定品质，按品质合并成若干 `task_results` 条目；后续读取和领取直接复用这些结果，不能重掷。

### 锁定引用

锁定的对象是伙伴的“站位”，不是简单的一对一忙碌标记。一个伙伴可以负责自己所在的生产格，同时通过特性支援多个相邻任务；只要仍有任意进行中任务引用它，玩家就不能将它移到别处。

```text
任务锁定伙伴 = 本格负责人
             ∪ 本次实际生效的空间支援来源

伙伴可移动 = 不存在引用该伙伴的进行中任务
```

任务保存直接负责者 `assigned_partner_ids`、支援来源 `support_partner_ids` 和已经展开的 `applied_effects`。任务完成时移除自己的引用；被多个任务引用的伙伴要等最后一个相关任务完成后才能移动。前端应展示伙伴正在负责和支援的格子，以及预计最晚解锁时间。

伙伴在被相邻任务锁定后仍可以在自己已经驻场的格子开工，因为这不会改变站位；它不能借此改驻另一个格子。伙伴的完整产业能力只加入自己直接负责的任务，支援其他格子时仅施加特性明确声明的效果。

### 格子拓扑与空间支援

空间效果只在任务开始瞬间根据当时的站位判定，并写入任务快照，此后不动态重算。提供效果的伙伴会被该任务加入锁定引用，因此不能通过让同一伙伴依次短暂停留来为大量任务刷取全程增益。

首版农田只把上下左右四格视为相邻，不计算斜角。底层规则使用生产格 ID 和邻接关系，不把所有设施强制建模为矩形坐标；猪圈、加工台等区域可以声明自己的邻接图。后续特性可使用显式目标形状，例如：

- 上下左右相邻格；
- 同一行左右一格或同一列前后一格；
- 指定方向的一格；
- 距离两格但数值较弱的远程支援；
- 满足作物、设施或产业标签的指定格。

每个空间特性必须配置作用目标、是否包含自身、叠加组、最大层数和叠加方式。默认只取同一叠加组中的最高效果；允许相加的效果必须另设总上限。空间效果不能隐式改变另一个已经开工的任务。

## 主角天赋

主角每次升级获得天赋点，可投入七种产业各自的天赋树。每棵树包含四类节点：

- **产业能力**：稳定增加主角在该产业的能力值，是最常见的小节点。
- **产业编制**：增加对应产业可以同时驻场的伙伴总数。
- **伙伴等级上限**：提高伙伴参与该产业任务时可生效的等级上限。
- **特殊效果**：解锁单格第二个协作者位置，或改变速度、产量、品质和产业联动规则；高阶节点可以开放“奇迹”品质的必要条件之一。

产业编制、第二协作者位置和等级上限会放大整个伙伴库，属于稀疏的里程碑节点；产业能力可以作为连接路线的常规节点；其他特殊效果用于形成速度、产量、品质等不同分支。

玩家从 2 级开始，每次升级获得 1 个公共天赋点；七棵产业树共享这些点数。七个方向统一在经营 Dashboard 展示和操作，各产业页面只处理本产业的生产任务，不重复嵌入局部天赋树。当前只开放采集树中的两个编制节点：2 级节点使采集编制 `+1`，4 级后续节点再使采集编制 `+1`。采集编制等于产业基础编制与已点亮节点加成之和，限制同时派驻在采集点的伙伴数量。首版节点点亮后不提供重置；增加重置功能前必须先定义进行中任务和超额派驻的处理方式。

主角产业能力对该产业的所有任务提供公共底值，但伙伴能力只加入其实际派驻的任务。对某个任务，基础总能力为：

```text
伙伴有效等级 = min(伙伴实际等级, 主角在该产业的伙伴等级上限)

伙伴有效能力 = 该倾向的基础能力
             + 有效等级成长
             + 已生效的突破成长

任务产业能力 A = 主角对应产业能力
               + Σ 本格直接负责伙伴的有效能力
```

相邻格伙伴的完整能力不加入 `A`，只计算其特性明确提供的支援数值。伙伴特性通常不直接并入 `A`，而是在后续结算中修改规则。这样能力值负责可比较的稳定成长，特性负责构筑差异。

## 伙伴

伙伴只有 3 星、4 星和 5 星三种稀有度，并拥有一至三个产业倾向。每个倾向有独立能力值；一个伙伴拥有多个倾向代表可派往更多类型的任务，不代表同一次任务可以重复贡献能力。

### 稀有度与能力曲线

以相同有效等级、相同突破阶段、同类定位的 3 星伙伴为 `100%` 基准：

| 稀有度 | 建议基础能力 | 主要价值 | 培养特征 |
| --- | ---: | --- | --- |
| 3 星 | 100% | 单产业专精、容易成型 | 获取和突破成本最低 |
| 4 星 | 110% | 队伍核心、稳定联动 | 成本和强度居中 |
| 5 星 | 120% | 独特机制、跨产业或灵活配置 | 成本最高、成型更慢 |

表中比例是同定位伙伴的设计基线，不要求所有伙伴精确同值。最终配置允许在此前讨论的约 `100% / 108%—112% / 115%—122%` 区间内调整，但不能用星级制造成倍的裸数值差距。倾向数量也不与星级强绑定；多倾向的价值主要是调度弹性。

### 倾向数量与基准数值

裸能力值不体现星级差异，星级倍率在 `ability_at` 里统一乘上；倾向的配置数值只由**倾向数量和槽位**决定。倾向越多越灵活，但每个槽位的数值越低，满级能力按下面的顺序严格递减：

```
单方向 > 双方向主 > 三方向主 > 双方向副 > 三方向第二 > 三方向第三
```

| 槽位 | 1 级 | 60 级 |
| --- | ---: | ---: |
| 单方向 | 37 | 235 |
| 双方向 · 主 | 34 | 223 |
| 双方向 · 副 | 27 | 168 |
| 三方向 · 主 | 32 | 205 |
| 三方向 · 第二 | 25 | 158 |
| 三方向 · 第三 | 22 | 134 |

1 级数值是硬基准，所有伙伴的同一槽位取值保持一致，新伙伴不在这一端做差异化。60 级数值以基准为中心，常规微调控制在 `±5` 内；个别伙伴可以有意超出这个范围，但那是逐个决定的设计选择，需要清楚自己在用裸数值制造强度差，通常应优先考虑用特性表达。方向顺序即槽位顺序，`tendencies` 数组的第一项是主方向。这份基准是写给设计的约定，不作为回归测试的断言。

伙伴拥有等级、星级和突破。每个伙伴最多突破两次：未突破、一次突破和二次突破的等级上限分别为 20、40 和 60，满级固定为 60。等级提供平滑的能力成长，突破提高成长上限并可解锁或强化特性。伙伴参与完成生产任务时，每完整工作 12 分钟获得 1 点时间经验，每消耗 1 点任务体力额外获得 2 点体力经验，单次任务至少获得 1 点；到达当前等级上限后经验保留在上限。伙伴也可以消耗经验书培养。3 星和 4 星伙伴可消耗同行印记升星，星级倍率在计算产业能力时统一应用。玩家仓库以伙伴稳定 ID 保证唯一持有，抽到重复伙伴时按原始稀有度转化为同行印记，不能新增第二个同 ID 仓库实例。

每个产业倾向分别配置 1 级和 60 级能力，等级间属性由伙伴选择的成长曲线插值：

- **早熟**：前期获得较多成长，后期逐渐放缓；
- **线性**：每级提供相同的成长比例；
- **晚熟**：前期成长较慢，后期加速。

三种曲线在 1 级和 60 级必须严格落在配置端点，不能通过曲线改变满级总能力。突破只限制当前可达到的等级上限，不另行制造未配置的隐藏裸属性。

每个突破阶段拥有一张独立的 9:16 伙伴插画。管理员可以上传任意常见比例的 JPG、PNG 或 WebP 原图，再用可视化选区确定 9:16 区域；服务端负责边界复核、裁剪、将大图缩小到最高 1080×1920，并统一编码为 WebP。三个突破阶段分别保存一套头像裁剪坐标 `x / y / w / h`，由使用方从各自处理后的插画中裁剪，不保存重复头像图片。后台通过可拖动、四角可缩放的裁剪组件维护这些参数，不要求管理员手工推算像素。最终插画上传到统一对象存储并经 CDN 分发；静态配置只保存稳定 object key、宽高和内容类型，不依赖应用服务器直接提供原图。

伙伴静态配置保存在 `data/partners.json`，后台允许管理员维护稳定 ID、名称、星级、简介、产业倾向、两端能力、成长曲线、特性代号、三阶段插画和头像裁剪参数。缺少任一阶段插画的配置视为未完成卡片，不能作为可发布内容使用。

### 玩家伙伴仓库

玩家存档只保存已经持有伙伴的稳定 ID、当前等级与经验、星级、突破阶段和获得时间，名称、插画、倾向、特性等展示内容始终从当前静态配置读取。伙伴仓库不允许出现重复 ID，接口和存档模型都必须校验该约束。

玩家可以从侧边导航进入伙伴仓库，浏览已有伙伴并打开详情；详情展示当前突破阶段插画及头像、等级上限、经验、星级、倾向能力和特性。升级可消耗经验书，升星可消耗同行印记；突破严格读取每名伙伴配置的阶段材料，当前材料表为空时接口和前端统一显示“暂不能突破”，不保留无配置的旧突破分支。管理员后台可以按玩家名称或 Player ID 搜索，并向玩家发放尚未持有的伙伴；发放操作通过应用服务原子写入，重复发放返回冲突，不能依赖前端过滤保证唯一性。

### 特性

特性用于表达公式以外或改变公式结构的效果，例如：

- 某类作物的收获数量增加，但不影响其他作物；
- 雨天种植不消耗某项资源；
- 加工时有概率返还一种原料；
- 与具有指定倾向的另一伙伴共同派驻时触发联动；
- 为上下左右相邻格提供品质能力，或为指定方向的格子缩短时间；
- 满足季节、设施或任务条件时获得“奇迹”判定资格。

特性必须明确触发阶段、作用范围、叠加方式和上限。空间与跨产业特性只读取本次任务的开工快照或已结算的明确状态，不隐式修改另一个正在进行的任务。

配置文件只保存特性代号，例如 `1 / 2 / 3 / 4`。代号的名称、说明和效果处理器由 Python 注册表定义；任务结算根据配置代号依次分发到已注册处理器。JSON 中不得保存表达式或任意可执行代码，未实现的代号可以用于内容筹备，但不会产生游戏效果。

## 农作时间

农作能力可以缩短种植时间，但采用收益递减并将效率设置为最高 `300%`：

```text
效率 η = 1 + 2 × A / (A + 作物时间难度)
实际时间 = 基础时间 / η
```

- `100%` 效率对应基础时间，`300%` 效率对应基础时间的三分之一。
- `A` 增长时效率逐渐接近 `300%`，任何天赋和特性组合都不能突破该硬上限。
- `作物时间难度` 随内容阶段提高，用来控制相同能力在后期作物上的效果。

产量使用独立公式和独立上限，不能把时间缩减后的收益再次无界放大。平衡时应观察单位现实时间收益、单位体力收益和伙伴占用时长。

## 五档品质

所有可带品质的农作物、采集物、矿石、畜产品和加工品统一使用整数等级保存：

| 等级 | 名称 | 定位 |
| ---: | --- | --- |
| 1 | 普通 | 基础产出 |
| 2 | 良品 | 稳定提升后的常见产出 |
| 3 | 上品 | 中后期主要追求 |
| 4 | 臻品 | 高能力与完整配置的成果 |
| 5 | 奇迹 | 隐藏或苛刻条件下的极稀有产出 |

常规成长只保证前四档可达。奇迹品质不作为主线任务、设施升级或常规配方的强制材料，主要服务收藏、特殊委托和惊喜收益。

### 品质概率

每种作物配置四个累计阈值 `T2 < T3 < T4 < T5`、共同或独立的分布宽度 `W`，以及奇迹概率上限。任务的品质能力为：

```text
Q = 任务产业能力
  + 土壤修正
  + 肥料修正
  + 设施修正
  + 天气与季节修正
  + 天赋和伙伴特性修正
```

定义逻辑函数：

```text
S(x) = 1 / (1 + e^(-x))
G2 = S((Q - T2) / W)
G3 = S((Q - T3) / W)
G4 = S((Q - T4) / W)
```

`Gn` 表示品质至少达到第 `n` 档的累计概率。奇迹需要先通过配置声明的资格条件：

```text
没有奇迹资格：G5 = 0
具有奇迹资格：G5 = min(G4, 奇迹概率上限 × S((Q - T5) / W))
```

各档最终概率为：

```text
P(普通) = 1 - G2
P(良品) = G2 - G3
P(上品) = G3 - G4
P(臻品) = G4 - G5
P(奇迹) = G5
```

阈值必须保证累计概率单调，配置加载时需要验证。奇迹概率上限建议常规为 `0.1%—0.5%`，极特殊组合也不超过约 `1%`。当前售价倍率采用 `1.0 / 1.2 / 1.5 / 2.0 / 3.0`，先计算每件单价并按四舍五入取整，再乘以出售数量；加工配方和委托以后可以对品质设置不同权重。

当前农作、采集、加工与矿产实现中，`Q` 先等于任务对应的产业总能力，也就是主角基础能力与本格驻场伙伴有效能力之和；土壤、肥料、设施、天气、季节、天赋和伙伴特性修正暂为 `0`。当前内容尚未配置奇迹资格，因此正常游玩最高产出臻品；资格条件接入后不需要更改概率与库存结构。品质判定以单件为单位：一次采集、采矿、农作收获或加工任务里的每一件产物都用同一份冻结概率各掷一次，结果按 (物品, 品质) 合并成若干库存条目。整批产物因此不再共享一个品质，期望收益不变，但高品质不再以“整批开出”的形式出现。

## 采集

采集点执行的探索任务不再逐项判定掉率，而是从一个加权产出池里抽取若干次。每个任务配置产出池（每项写明物品、抽取权重和单次抽中的件数区间）与抽取曲线 `draws.base_draws`、`draws.ability_bonus`、`draws.difficulty`：

```text
抽取次数 = ⌊base_draws × (1 + ability_bonus × A / (A + difficulty)) + 0.5⌋
```

`A` 与时间效率、品质使用同一个产业总能力，因此伙伴的采集能力同时抬高三条轴：更快、抽得更多、每件产物的品质分布更好。抽取次数在开工时算入任务快照的 `draw_count` 并冻结，之后的升级或配置热更新只影响下一次任务。

产出池不设保底项：权重决定长期配比，单次探索允许颗粒不均。结算时先按权重逐次抽取物品与件数，再对每一件产物单独判定品质，最后按 (物品, 品质) 合并成 `task_results`。旧存档里仍在进行、按独立掉率开工的任务保留原结算方式（快照中 `draw_count` 为 `0`、产出池带 `chance`），保证开工时承诺的产出不被规则变更改写。

## 矿产

矿产从居民 2 级开放，首版提供 2 级的赤岩山脚与 4 级的月石深洞。每个矿点独立执行矿脉任务，保存固定时长、体力消耗、基础产量、能力产量加成、经验和品质参数；矿石使用与农作、采集相同的五档品质库存与售价倍率。体力每 12 分钟恢复 1 点，配置校验要求固定采矿时长与对应体力的自然恢复时间一致，使采矿相当于预支这段时间内恢复的体力。

玩家可以独自采矿，也可以选择派驻一名具有矿产倾向的伙伴。伙伴的矿产有效能力提高产量与品质能力，但不会缩短固定开采时间，开工后锁定至任务成熟；矿产编制、跨产业唯一派驻、任务快照和固定结算结果均复用通用生产规则。首版不实现工具耐久、矿层随机地图或勘探事件，这些规则若加入必须作为显式内容或任务效果保存。

## 加工配方

加工在独立工位执行，可以由玩家独自开工，也可以派驻具有加工倾向的伙伴。伙伴参与时使用加工有效能力缩短时间并提高任务品质能力，开工后锁定至任务成熟。配方原料、实际扣除的品质和数量、成品、时间、经验与品质参数全部写入开工快照；配置热更新不能改变进行中的消耗或产出。

每个配方必须显式配置 `unlock_condition`，至少包含稳定的 Python 注册钩子代号 `hook` 和参数 `params`。不存在“缺少条件就默认解锁”的分支：缺少条件、引用未知钩子或参数不合法都会使内容配置加载失败。JSON 不执行任意代码；新增任务进度、物品发现或复合条件时，应在服务器注册新的纯判定钩子，再由配方引用其稳定代号。首版钩子为 `player_level`。

开工时原料在 repository 原子更新内扣除，任一原料不足则整个任务不成立。首版自动从最低品质开始消耗，允许同一种原料跨多个品质档补足数量，并把每一档的实际消耗分别写入 `consumed_inputs`。原料品质暂不参与成品品质计算，成品 `Q` 仍来自加工产业能力；以后如果配方需要品质继承或最低品质门槛，必须作为配方规则显式配置，不能暗中改变通用扣料策略。

## 传送门

传送门是主线推进的载体，也是把各产业产物回收进主线的出口。每座传送门配置若干项贡品，每项写明物品、数量、可选的最低品质和交齐后的回礼；整座门另有一份全完成奖励。

贡品分次累积：玩家一次交多少都记进 `delivered`，服务端会把请求数量收敛到"还缺的"和"仓库里够格的"两者取小，交付数量为零或超出仓库存量视为失败，不做部分扣除。交满一项立刻结算该项回礼并写下 `completed_at`，重复上报不会再发一次；所有项都交满时结算全完成奖励并记录传送门完成时间。配置里调高数量不会让已完成的项重新变成未完成，因为完成看的是 `completed_at` 而不是当前数量对比。

配置了最低品质的贡品只接受该品质及以上的库存，够格的品质里优先扣最低的一档，玩家不会因为交贡品而被吃掉臻品。低于门槛的库存既不计入可交数量，也不会被扣除。

解锁是树状而非线性：`prerequisites` 列出必须先完成的传送门，一座门完成后可以同时带出多条支线，一条支线也可以要求同时完成多座门。内容加载时会拓扑排序检查成环，成环会让整棵子树永远打不开，所以直接让内容加载失败。等级门槛与前置传送门是并列条件，快照里只报当前第一个未满足的原因，前置完成情况另行逐条下发。

奖励结构 `RewardDefinition` 由贡品和全完成共用，支持红叶币、经验、天赋点、物品（可指定品质）和伙伴加入。传送门发放的天赋点记在存档的 `bonus_talent_points` 上，与升级获得的点数进同一个可用池。奖励里的伙伴如果玩家已经拥有则跳过，不会重复发放。

## 今日委托

每天有一位随机 NPC 上门要一件产物，交付获得配置额度的枫火。要求的物品只从玩家**已经能自己产出**的东西里挑：作物、采集产出、矿产和已解锁配方的加工品，条件直接读现有内容配置，不另维护一份清单；种子和抽卡专属消耗品不会被要求。委托暂不要求品质，扣库存时从最低品质开始扣。

难度用档位表达：每个可生产物品在 `commissions.entries` 里挂一个 `tier`，`commissions.tiers` 为每个档位配置平日权重、幸运日权重和要求件数区间，越难产出的档位平日权重越低。新增一个 `produce`/`material`/`product` 物品却没有定档会让内容加载直接失败，必须要么定档要么显式写进 `excluded_item_ids`，避免新物品静默地永远刷不出来。

每个玩家有一个由 `player_id` 派生、跟随账号永久固定的幸运日（星期几）。幸运日改用另一张权重表，整体压向高难度档，报酬相应提高；低等级玩家在幸运日可能一个高档物品都没解锁，此时退回他手上最难的那一档，而不是掷空。

委托按配置的刷新时区和刷新点划分自然日，换日时整条重掷。掷出的内容在首次读取时随原子更新一起冻结，掷点由 `(player_id, 当日)` 派生，因此并发重试不会换内容，玩家当天升级也不会改掉已经看到的委托。

交不掉的委托可以转发进公共转发池，由别人代交。代交完成后委托人拿 `forward_owner_share`、代交者拿 `forward_taker_share`，两份合计可以超过 100%——多出来的部分是对社交行为的补贴，不是把一份奖励切开。每人每天代交次数有上限。转发出去之后本人不能再自己交，但只要还没被人接走就可以随时收回，收回后自己交仍是全额。池子不设"接单锁定"，谁先提交谁拿到代交那一份，避免占坑不交还要配超时释放。

## 招募与抽卡

伙伴可由抽卡和常驻招募获得。当前常驻池在居民等级达到配置门槛后开放，消耗引路枫叶；枫火只能按配置比例兑换为引路枫叶，不支持反向兑换。抽取可能获得伙伴或任务道具，最初若干抽不会出现道具；重复伙伴转化为同行印记。除预先明确标记的极少数特殊伙伴外，未来 UP 卡池结束后伙伴应进入常驻池；进入时间和例外必须在卡池配置中显式记录。

- 卡池、概率、UP、保底和转常驻规则均为服务器版本化配置。
- 抽取结果使用服务器随机源，并与保底状态、消耗、历史流水原子提交。
- 每次请求携带幂等 ID，避免重试造成重复扣费或重复发放。
- 常驻池扩大后应提供定向、心愿单或招募标签等收敛手段。
- 招募以公开标签、等待时间和可见规则换取伙伴，补充低星培养并提供长期目标。

任务道具分为开工时使用和进行中使用两类，消耗与任务创建/修改在同一个原子更新中完成。开工快照必须冻结道具效果；其中“一片金叶”使本次任务使用 `2×W` 的完整奇迹曲线且忽略原任务奇迹概率上限，“夜灯茶”只可令剩余时间未超过配置门槛的进行中任务立即完成。

## 数值验证基线

新增作物、伙伴、天赋或特性时，至少比较以下指标：

- 金币/小时、经验/小时和单位体力价值；
- 单个生产格的回本时间与离线容忍时长；
- 伙伴占用时间和不同星级的培养回收周期；
- 普通至臻品的概率分布，以及奇迹概率是否越过上限；
- 无抽卡、常规 3 星配置和高练度配置之间的通关与收益差距。

平衡测试应固定主角等级、天赋投入、伙伴有效等级、生产格数量和内容解锁阶段。不要只比较单次收获，因为时间缩减、并行格数量和伙伴占用会共同影响长期收益。
