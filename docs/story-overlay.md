# 剧情 overlay

剧情 overlay 是一层可以随时插话的演出层，不要求玩家先进入某个"剧情模式"。它只有三个可见部分：背景图、角色对话框、对话框旁边的立绘。

## 两种模式

剧本自己决定用哪种模式，前端不需要额外开关：

- **舞台模式**：剧本里出现了带 `asset_id` 的 `background` 步骤。overlay 全屏接管，按 16:9 居中留黑边排版，触摸设备会请求全屏并尝试 `screen.orientation.lock('landscape')`；锁不上（iOS Safari 不支持方向锁定）时显示旋转提示遮罩，玩家把手机横过来后继续，遮罩上也留了跳过入口。
- **插话模式**：剧本没有背景步骤。对话框浮在当前页面底部占满宽度，立绘不占对话框的宽度，而是站在对话框**后面**，下半截被半透明的对话框压住、透出来一点。不请求全屏、不改变屏幕方向，但整层铺满屏幕并接管点击：插话没说完之前点不到页面上的东西，点哪儿都是推进对话。移动端对话框会自动避开底部导航栏。

一句台词一次点击推进，点击整层任意位置都算推进；桌面端空格/回车推进，Esc 跳过。

## 剧本格式

剧本是手写 JSON，一个文件一个剧本（也允许一个文件放一个数组），目录是 `data/story/`。内容在加载时由 Pydantic 校验，未知触发 hook、非法参数、引用不存在的素材都会让内容加载直接失败。

```json
{
  "id": "welcome_farm",
  "title": "第一次走进农场",
  "priority": 10,
  "trigger": { "hook": "cue", "params": { "cue": "view:farm" }, "repeatable": false },
  "steps": [
    { "type": "background", "asset_id": "autumn_gate" },
    { "type": "portrait", "slot": "left", "asset_id": "maple_smile", "transition": "slide" },
    { "type": "dialogue", "speaker": "枫糖", "text": "这块地空了一整个冬天啦。", "focus": "left" },
    { "type": "portrait", "slot": "left", "visible": false }
  ]
}
```

`rewards` 是可选的，剧本第一次播完时结算一次，用的是和传送门同一套 `RewardDefinition`：

```json
"rewards": {
  "coins": 40,
  "experience": 10,
  "talent_points": 0,
  "items": [{ "item_id": "carrot_seed", "quantity": 5 }],
  "partner_ids": ["fein"]
}
```

字段都可以省略。奖励在 `POST /api/red-leaf-town/story/<id>/seen` 里发放，同一个剧本重复上报不会再发一次（第二次起 `granted` 为 `null`），玩家已经拥有的伙伴会跳过；`repeatable: true` 的剧本不允许带奖励。发放走的是存档写入，接口会把结算结果和新存档一起返回，前端直接采用并弹一条"获得 …"，不用等下一次轮询。奖励引用的物品和伙伴都必须存在，否则内容加载失败——所以剧本的加载现在也依赖 `data/game.json`。

步骤只有三种：

| 类型 | 说明 |
|------|------|
| `background` | 换背景；`asset_id` 留空表示撤掉背景 |
| `portrait` | 在 `left` / `center` / `right` 显示立绘，`visible: false` 表示收起该槽 |
| `dialogue` | 一句台词；`speaker` 留空是旁白，`focus` 决定名牌贴在哪一侧 |

背景和立绘都可以写演出参数，全部可省略，省略后就是原来的表现，所以老剧本一个字都不用改：

| 字段 | 适用 | 取值 | 默认 |
|------|------|------|------|
| `transition` | 背景 | `fade` / `cut` | `fade` |
| `transition` | 立绘 | `fade` / `slide`（从外侧滑入）/ `cut` | `fade` |
| `duration` | 两者 | 0–3 秒 | 背景 0.45、立绘 0.28 |
| `flip` | 立绘 | 水平翻转，改立绘朝向 | `false` |
| `layout` | 立绘 | `scale` 0.2–4.0、`offset_x` -1.5–1.5、`offset_y` -0.8–0.8 | 不写就用素材调好的站位 |

`layout` 只影响写了它的那一步，范围比素材默认站位放得开——`offset_x` 可以一直推到画面外，用来做"角色走出去"这类演出。收起立绘那一步的淡出沿用它出场时的转场设置。

立绘一律按透明底素材处理，不提供黑底滤色选项：插话模式的 overlay 是 `position: fixed` 的独立 stacking context，`mix-blend-mode` 混不到下面的页面，滤色在那里无法按原义生效，所以统一要求上传透明底 PNG（上传转码保留透明通道）。

立绘的尺寸和位置是**素材自己的属性**，保存在 `data/story_assets.json` 里，剧本不重复写，同一张立绘在所有剧情里的站位一致。两种模式的画框比例差得远，所以各存一套：`inline_layout` 和 `stage_layout`，字段相同：

| 参数 | 范围 | 含义 |
|------|------|------|
| `scale` | 0.4–4.0 | 相对该模式默认高度的倍数。默认高度在舞台模式是舞台满高，在插话模式是 `min(40vh, 300px)`（移动端 `min(34vh, 220px)`）。缩放只改高度，脚下的基线不动，宽度朝远离贴边那侧生长 |
| `offset_x` | -0.5–0.5 | 横向平移，单位是立绘自身宽度的比例，正数往右 |
| `offset_y` | -0.5–0.5 | 纵向平移，单位是立绘自身高度的比例，正数往下 |

这些值在后台可视化调：`/red-leaf-town/admin/story` 的立绘卡片上点「位置」，会用真正的 overlay 起一个锁定的预览（点击不会翻页），拖滑块实时看效果，可以切左右站位、切插话/舞台模式（两种模式各自一套参数，分别调）、换预览背景，满意再保存。保存走 `PATCH /api/red-leaf-town/admin/story/assets/<id>`，一次写入两套 layout，后端复核范围。背景素材不允许带 layout 参数。读取旧结构时，直接挂在素材上的一套 `scale`/`offset_x`/`offset_y` 会迁移成两种模式共用同样的值。

复用伙伴插画的立绘（`partner_id`）没有素材记录，按默认值 1 / 0 / 0 显示。

立绘来源二选一：素材库的 `asset_id`，或者 `partner_id` + `breakthrough` 直接复用伙伴卡片已有的 9:16 插画。伙伴插画还没上传时该步骤退化为不显示立绘，不会让剧情播不下去。

## 触发

服务端负责判断，前端只负责发信号。玩家进入某个页面或完成某个操作时，前端 `POST /api/red-leaf-town/story/cue` 带上信号代号，服务端评估所有还没看过的剧本并返回该播的那些；播完前端 `POST /api/red-leaf-town/story/<id>/seen`，剧本 ID 记进存档的 `seen_story_ids`（schema v9）。`repeatable: true` 的剧本不受已看过约束。

信号代号形如 `view:farm`、`action:harvest`、`action:collect_mining`，由前端路由和 `stores/game.ts` 里的动作发出。

触发条件由 `src/red_leaf_town/story_triggers.py` 的 Python 注册表解释，剧本里只写 hook 代号和结构化参数，不写可执行表达式：

| hook | 参数 | 含义 |
|------|------|------|
| `cue` | `cue` | 收到指定信号 |
| `player_level` | `level` | 居民等级达到 |
| `has_item` | `item_id`, `quantity` | 仓库里有指定数量的物品（不分品质） |
| `owns_partner` | `partner_id` | 已经拥有某个伙伴 |
| `talent_unlocked` | `node_id` | 已经点亮某个天赋节点 |
| `portal_completed` | `portal_id` | 已经完成某座传送门 |
| `all_of` / `any_of` / `none_of` | `conditions` | 组合上面的条件，最多嵌套 4 层 |

不带 `cue` 条件的剧本在任何信号下都会被评估，所以"升到 5 级就演一段"不需要专门的信号。新增触发方式的正确做法是注册一个新 hook，而不是在页面里写特判。

## 素材

图还没画好的时候，可以先在 `data/story_assets.json` 里手写一条 `asset_key` 为空的占位素材，剧本照常引用它：占位素材没有 URL，演出时这一步静默降级（背景不画、立绘不显示），舞台模式仍然按背景步骤判定。后台的素材卡会标出"占位"，之后用**同一个素材 ID** 上传真图就会原地替换，剧本不用改。

背景和立绘在 `/red-leaf-town/admin/story` 上传，沿用宿主统一的 CDN provider：服务端校验格式、按类型限制长边（背景 2560、立绘 1920）、统一转码 WebP（保留 PNG 透明通道），只把 object key 存进 `data/story_assets.json`。剧本引用素材 ID，不引用 URL。仍被剧本引用的素材不允许删除。

换图要显式覆盖：上传时 ID 已存在会直接报 `asset_exists`，带上 `overwrite` 才会替换，素材卡上的「替换」/「补图」按钮就是把表单填好并勾上这个选项。覆盖只换图——名称留空时沿用原名，立绘调好的 `inline_layout` / `stage_layout` 也会保留，所以补完图不用重新调站位。素材类型不能被覆盖改掉（剧本会因此失效），要改类型只能换 ID 或先删掉原素材。旧的 CDN object 不会被删除：object key 带内容摘要，覆盖后是一个新对象，旧文件留在 CDN 上。

剧本 JSON 和素材目录都有进程内缓存，改完文件后在后台点"重新读取剧本"（`POST /api/red-leaf-town/admin/story/reload`）即可生效，不需要重启服务。

## 剧情编辑器

`/red-leaf-town/story-editor` 是排剧情用的可视化编辑器，任何登录玩家都能打开——它是给社区共建准备的，不需要管理员 Token，也**不会写进游戏**。它只管剧情本身：背景、立绘、台词，以及上面那几个演出参数。

**要登录才能用**，因为上传要留上传者记录。没登录时页面是一张登录卡。小于 900px 的屏幕直接劝退——这是工作区，不做窄屏适配。第一次打开且本地没有草稿时，编辑器会拿游戏里现成的那段全屏剧情生成一份 `demo_` 开头的示例草稿当起手。

**编辑器只产出全屏舞台剧本**：新建草稿就带一个背景步骤，没有选好图的背景会在校验里报出来。插话模式仍然是播放器支持的形态（`fein_farm_greeting` 就是），但不再从编辑器产出。

布局是左右两栏，高度全部锁死、页面不滚动：

- **右栏**只有两块，各占**正好半屏高**——上半是整块预览，下半是整块参数面板。栏宽由半屏高按 16:9 反推（`calc(50dvh * 16 / 9)`），所以预览永远是严格的 16:9 且刚好填满上半区。
- **左栏**拿走剩下的宽度，从上到下是：工具栏（标题／撤销重做／剧本信息／草稿箱／导入导出）、当前选中那一步的标题与翻页／删除／试播、操作列表、添加操作、问题提示。

- **操作列表读起来像剧本**。对话行用衬线体显示真实台词，背景和立绘是压低一档的舞台指示行，扫一眼就能当故事读。可以拖拽排序，右侧的 × 删除那一步。
- **选中即定格**。点哪一步，预览就把前面所有步骤叠起来，画面停在那一步，不用从头播。想看转场和节奏就按「全屏试播」，走的是玩家端同一套 overlay。
- **撤销重做**。`Ctrl+Z` / `Ctrl+Shift+Z`，连续打字算一次撤销。`Ctrl+D` 复制当前步骤，方向键切换选中，`Delete` 删除。

触发条件和奖励**不在编辑器里配**——它们要配合游戏进度和经济决定，由维护者最后定。作者在「剧本信息」里用大白话写清楚这段剧情什么时候该播、建议给什么奖励就行。

草稿存在浏览器的 localStorage 里，换设备或清缓存就没了，所以写完要**导出**。导出的是一份剧本 JSON，多带一个 `metadata` 块（作者、触发说明、奖励建议）；后端加载时会忽略这个块，所以同一个文件既能再导入编辑器接着改，也能在补好 `trigger` 之后直接放进 `data/story/`。导出时带的是占位 trigger（`cue: view:dashboard`），**合并前必须换成真正的触发条件**。

### 选图与玩家上传

选背景和立绘都是一个带搜索框的弹窗（素材上百张之后网格铺开根本没法看），可以按「全部 / 公共 / 我传的」筛。参数面板上只留当前选中那张图的缩略图，点开才是弹窗。

弹窗底部可以直接传图，走 `POST /api/red-leaf-town/story/uploads`：服务端校验格式、按类型限长边、转码 WebP 推到 CDN，**本地不留图**，只把 object key 和上传者记进 `data/story_uploads.json`（这个文件不入版本库，里面有 oauth sub）。

居中槽 `center` 以舞台中线为基准落位，`offset_x` 仍然是相对立绘自身宽度的平移。三个槽在舞台上按左、中、右的 DOM 顺序叠放。

传完一张立绘会直接进「调整默认站位」：左边是真正的舞台预览（和演出时同一套渲染），右边是缩放和偏移滑块，拖完保存即写入这张图的默认站位。之后也可以在弹窗里从自己传的图上点「调整」重新进来。改动走 `PATCH /api/red-leaf-town/story/uploads/<id>`，只能改自己传的图的名称和站位；背景没有站位可调，传完直接选用。这一套默认站位和公共素材的 `stage_layout` 是同一个角色——剧本里的单步 `layout` 仍然可以覆盖它。

几条硬规矩：

- **只能看到公共素材和自己传的图**。别人传的图既不列出来，也不能按 ID 删。
- **风控**：同一个上传者一小时内最多传 30 MB，按收到的原始字节算。配额在写索引时于锁内复核一次，并发同时传不会超额。单张仍然不超过 12 MB。
- 上传的素材 ID 形如 `up_<12位十六进制>`，和公共素材分属两个命名空间，玩家顶不掉剧本正在用的图；这个格式同时满足 `StoryScript` 对 `asset_id` 的校验，所以导出的剧本可以直接引用。
- 上传的图**不在** `data/story_assets.json` 里。剧本引用了社区图的话，导出文件的 `metadata.community_assets` 会把它们列出来（ID、类型、名称、object key），**维护者要先把这些图收进公共素材库，剧本才能加载**，否则内容加载会报 `references unknown assets`。

编辑器通过 `GET /api/red-leaf-town/story/resources` 一次拿齐公共素材、可用作立绘的伙伴插画、自己传的图、剩余上传额度和示例剧本。没图的占位素材和没插画的伙伴不会列出来——选了也画不出来。
